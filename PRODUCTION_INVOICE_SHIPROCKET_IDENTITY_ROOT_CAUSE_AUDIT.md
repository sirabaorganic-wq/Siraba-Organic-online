## 4. SELLER NAME SOURCE

### Why is `Rajesh Kumar Thakur` appearing as Seller?
1. **On Shiprocket Manifest (Document A):**
   - In Shiprocket, the manifest header and the carrier handover signature block pull from the **Shiprocket Account Profile Legal Name / Company Setup** (`Settings -> Company Details`).
   - The live Shiprocket account used by the platform was registered under the personal name of the founder: **Rajesh Kumar Thakur**.
2. **On the Shiprocket Tax Invoice (Document B):**
   - When an order is created in Shiprocket via `/orders/create/adhoc`, Shiprocket checks if a `reseller_name` or custom seller is specified in the payload.
   - In `backend/services/shiprocketService.js` (lines 466–494), the payload omits `reseller_name`.
   - Consequently, Shiprocket falls back to printing the Shiprocket Account Owner / Company Name: **Rajesh Kumar Thakur**.

## 8. INVOICE NUMBER SOURCE

### Why is `Retail0003` appearing?
- Repository search for `Retail` or `Retail0003` confirms **zero references** in Siraba's numbering generators.
- Siraba backend generates invoice numbers in strictly defined sequences:
  - Customer Product Tax Invoice: `[VENDOR-PREFIX]/26-27/000001` (e.g. `VND-2F34D3/26-27/000001`)
  - Legacy Siraba Invoice: `SO/26-27/000001`
  - Credit Notes: `CN/26-27/000001`
- `Retail0003` is Shiprocket's **internal auto-increment invoice sequence**. Shiprocket default invoice settings use the prefix `Retail` and generate sequential numbers (`Retail0001`, `Retail0002`, `Retail0003`) for all orders imported into the channel.

## 9. GST / TAX SOURCE

### Why does Document B display `IGST 0.00 / 0.00`?
1. In `backend/services/shiprocketService.js` (lines 480–486), the shipment creation payload passes:
   ```javascript
   order_items: vendorOrder.items.map((item) => ({
     name: item.name,
     sku: item.sku || 'SKU',
     units: item.quantity,
     selling_price: item.price,
     discount: 0,
   }))
   ```
2. **Missing Tax & HSN in API Payload:** The payload does **not** provide `tax`, `tax_percentage`, or `hsn` to Shiprocket.
3. Because Shiprocket received `selling_price: 349` with no tax parameters, Shiprocket's internal invoice generator treated the taxable value as ₹349.00 and the tax as **₹0.00 (0% IGST)**.
4. Furthermore, the order (`6abaadb637d3f5ac2e6747b2`) was placed on **September 28, 2026**, ten days before Phase D (Flat 18% GST Engine) was deployed.

## 15. ROOT CAUSE SUMMARY

The incident is driven by **three distinct root causes** across operations, external configuration, and API mapping:

1. **Root Cause 1 (Operational Workflow Divergence):**
   The warehouse/operations team printed shipping documents and invoices directly from the **Shiprocket Seller Dashboard** (`app.shiprocket.in`) rather than using Siraba's authoritative customer invoice download endpoints (`/api/invoices/:id/download`).
2. **Root Cause 2 (Shiprocket Account Profile Misconfiguration):**
   The Shiprocket account was registered under Rajesh Kumar Thakur's personal name and personal Gmail (`rajeshthakur2006@gmail.com`), with invoice prefix `Retail`. Shiprocket uses these profile details on all native manifests and invoices.
3. **Root Cause 3 (Shiprocket API Payload Incompleteness):**
   In `backend/services/shiprocketService.js`, the `/orders/create/adhoc` API payload omits `reseller_name`, `order_items[].hsn`, and `order_items[].tax`, causing Shiprocket to default to zero tax and the account owner's identity.
